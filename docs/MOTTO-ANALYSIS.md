# Motto 레퍼런스 분석

분석일: 2026-09-28. 분석만 수행하며 vinorleague에 새로운 디자인이나 모션을 적용하지 않는다.

## 확인 범위와 근거

현행 홈페이지·Work·Method·대표 사례의 공개 문서와 Motto가 직접 작성한 리브랜딩 설명을 확인했다. 자동 브라우저의 실제 접속은 Cloudflare 403으로 차단됐다. 따라서 현재 사이트의 스크롤 속도, 고정 구간 길이, 모바일 전환, 폰트 이름, easing, 구현 라이브러리는 실측하지 못했다.

시각 자료는 공식 리브랜딩 글에 실린 과거 홈페이지 이미지다. 로컬 사본: output/playwright/motto-reference.jpg. 메뉴에 Workshops와 Speaking이 있는 이 이미지를 현재 홈페이지의 캡처로 취급하지 않는다. 현행 공개 홈페이지에는 Programs·Services·Method가 있다.

문서에서 ‘확인’은 공식 공개 자료에 있는 내용, ‘해석’은 이를 바탕으로 한 디자인 판단, ‘확인 필요’는 실제 브라우저 검수가 필요한 부분이다.

## 1. 사이트 전체를 묶는 이야기

**확인:** 현재 홈페이지는 Ideas Worth Rallying Around®라는 문구를 전면에 내세운다. 회사 소개는 미래의 기술·문화·혁신을 만드는 기업을 대상으로 한다. 이름, 깃발 심벌, 슬로건, Method의 중심 아이디어가 하나의 브랜드 설명으로 이어진다. 리브랜딩 글은 Brutalism을 디자인 언어의 근거로 설명한다. [홈페이지](https://wearemotto.com/) · [공식 리브랜딩 설명](https://wearemotto.com/blog/motto-rebrand)

**해석:** 큰 타이포그래피의 힘은 회사가 주장하는 하나의 생각이 여러 화면에서 반복되고 증명되는 데서 나온다. 제목만 크게 만들면 이 연결이 생기지 않는다. vinorleague도 성장이라는 말과 실제 프로젝트·작업 방식이 어떻게 이어지는지 먼저 정리해야 한다.

## 2. 타이포그래피와 그리드

**시각 자료에서 확인:** 과거 공식 이미지의 큰 슬로건은 여러 줄로 나뉜다. 첫 줄은 넓게, 다음 줄은 우측으로, 마지막 줄은 다른 시작점에서 배치된다. 작은 회사 설명이 대형 제목 옆의 빈 영역에 들어간다. 상단 메뉴와 하단 링크는 상대적으로 작고 얇다.

**해석:** 제목의 줄마다 시작점이 달라도 화면 전체의 바깥 여백과 정보 영역은 정돈돼 있다. 비대칭은 글자의 길이, 본문 위치, 이미지 영역 사이의 관계로 구성된다. 모든 텍스트를 굵게 키우면 이 대비가 사라진다. 참고할 것은 대형 제목·읽을 수 있는 본문·작은 안내의 크기 차이와 공통 정렬선이다.

**확인 필요:** 현행 사이트의 실제 column 수, gutter, 폰트 패밀리, 반응형 글자 크기. 12열 그리드나 특정 상용 폰트라고 단정하지 않는다.

## 3. 색과 이미지

**확인:** Motto는 기존 검정 사이트를 차가운 회색/흰색으로 바꿔 더 열린 인상을 만들었다고 설명한다. 흑백이 기본 브랜드 색이며 보조색은 콘텐츠의 범주를 구분하는 데 사용한다. [공식 리브랜딩 설명](https://wearemotto.com/blog/motto-rebrand)

**해석:** 차분한 사이트 바탕은 프로젝트의 개성을 읽는 배경이 된다. 흑백을 참고한다고 작품 이미지의 색까지 없앨 필요는 없다. 현재 vinorleague의 컬러 masonry와도 함께 검토할 수 있는 원칙이다. 긴 웹 화면 캡처, 캐릭터 이미지, 브랜드 목업은 내용의 밀도가 다르므로 이미지 원본의 편집도 리스트 구성의 일부로 봐야 한다.

## 4. 메인의 콘텐츠 순서

**확인:** 현재 공개 홈페이지의 읽기 순서는 대형 선언 → 회사의 역할과 프로그램 안내 → 고객사 신뢰 → 대표 작업 → 글과 언론 → 고객 평가 → Method → 회사 소개다. 대표 작업에는 네 프로젝트가 노출된다. [홈페이지](https://wearemotto.com/)

**해석:** 방문자가 회사의 주장과 그 주장을 믿을 근거를 차례로 만난다. 제목, 작업, 고객 평가, 방법론은 서로 다른 역할을 맡는다. 섹션마다 같은 크기의 제목·본문·카드를 반복하기보다 정보의 중요도에 맞춰 밀도를 조절하는 편집이 핵심이다.

vinorleague의 현재 순서는 선언 → 스튜디오 철학 → 작업 → 서비스 → 고객사 → 글이다. 같은 컴포넌트를 재사용하더라도 각 섹션이 어떤 질문에 답하는지 명확히 하는 것이 먼저다. 기존 콘텐츠에 없는 평가나 성과를 만들어 넣지 않는다.

## 5. Work와 사례 상세의 역할

**확인:** Work는 카테고리 필터와 프로젝트 이름, 업종·성격 설명을 제공한다. 별도의 work-list 경로도 있다. 사례 상세는 프로젝트 개요, 기회나 문제, 전략, 표현, 적용 결과 등을 단계로 풀어낸다. Method는 중심 아이디어·비전·문화·브랜드의 네 단계를 설명하고 다음 단계로 이어지는 동작을 제공한다. [Work](https://wearemotto.com/work) · [Work list](https://wearemotto.com/work-list) · [Method](https://wearemotto.com/motto-method) · [Impel 사례](https://wearemotto.com/portfolio/impel-ai)

**해석:** 목록은 탐색을, 상세는 판단을 돕는다. 이미지 수나 크기만으로 설득하는 구조가 아니다. vinorleague의 현재 사례 상세에는 짧은 개요만 있으므로, 원본 자료가 확보되면 문제·선택·결과의 관계부터 보강하는 편이 타당하다. 자료 없이 결과나 수치를 만들면 안 된다.

**확인 필요:** 현재 Work 화면의 정확한 열 구성, hover 동작, 이미지/목록 전환 방식, 사례 하단의 다음 작업 전환 애니메이션.

## 6. 스크롤과 모션 — 사실과 추정을 구분

**확인:** Motto는 모든 페이지의 모션과 작은 인터랙션으로 웹사이트에 건축적인 느낌을 주려 했다고 직접 설명한다. [공식 리브랜딩 설명](https://wearemotto.com/blog/motto-rebrand)

**해석:** 이 설명의 참고점은 공간과 정보의 관계가 이어지는 경험이다. 모든 요소에 같은 등장 효과를 붙이는 규칙으로 해석할 근거는 없다. 섹션이 들어오는 순간, 제목이 완성되는 순간, 작업을 탐색하는 순간에는 각각 목적이 필요하다.

**현재 확인하지 못한 것:** 첫 화면이 빈 상태로 시작하는지, 히어로가 얼마나 오래 고정되는지, 각 글자가 스크롤에 직접 묶이는지, 페이지 전체에 관성이 있는지, 휠·터치·키보드에서 어떤 속도 차이가 있는지. GSAP·Lenis 등의 사용 여부도 확인하지 않았다. 이 항목들은 실제 접속 없이 Motto의 특징으로 적지 않는다.

## 7. 이번 vinorleague 스크롤 시안의 문제

아래는 Motto가 아니라 직접 만든 로컬 시안의 코드와 Playwright 측정 결과다.

- PC 900px, 모바일 600px의 추가 스크롤 구간 동안 히어로가 고정됐다. 사용자가 움직이는 거리와 화면 전진의 느낌 사이에 차이가 커졌다.
- 글자가 자기 높이의 105%를 이동하는 마스크 효과가 사용됐다. PC에서는 한 줄 약 190px의 움직임이며 스크롤 진행에 직접 연결됐다.
- 각 줄과 설명·링크가 분리된 구간에서 나타났다. 연속적으로 페이지를 읽는 흐름보다 단계별 조작을 요구하는 느낌이 강했다.
- 완료 후 제목의 opacity가 다시 0이 되는 오류가 실측됐다. PC scrollY=900, 모바일 scrollY=600에서 제목이 모두 사라졌다. 등장 후 안정된 화면을 읽을 시간을 제공하지 못했다.
- 키보드로 링크에 포커스할 때 화면을 즉시 이동시키는 처리도 있었다.

일반 휠 입력을 막는 코드가 없어, 이번 결과만으로 실제 스크롤 성능 저하를 확정할 수는 없다. 긴 고정 구간·큰 이동 거리·등장 순서·opacity 오류는 확인된 문제다. 관성 효과를 추가하는 것만으로 해결됐다고 판단하면 안 된다.

시안은 output/scroll-draft에 보관했다. 화면은 정적 기준 커밋 364fbbc로 복원했다. 새로운 모션은 적용하지 않는다.

## 8. 다음 구현 전에 확인할 기준

구현 계획이 아니라 평가 기준이다.

1. 첫 스크롤에 화면이 바로 반응하는가.
2. 등장한 제목이 안정적으로 남고, 완성된 문장을 읽을 시간이 있는가.
3. 앞 요소와 다음 요소의 등장 구간이 자연스럽게 이어지는가.
4. 섹션을 빠르게 지나가거나 거꾸로 올라가도 콘텐츠가 누락되지 않는가.
5. 모바일에서 데스크톱과 같은 긴 고정 구간을 강요하지 않는가.
6. 메뉴·프로젝트·텍스트 링크를 휠·터치·키보드로 즉시 이용할 수 있는가.
7. 모션 줄이기 설정과 JavaScript 없는 환경에서도 내용이 보이는가.

Motto를 더 확인할 때는 PC와 모바일에서 초기 화면, 첫 스크롤, 히어로 종료, Work 필터, 사례 전환을 연속 영상으로 비교한다. 실제로 보이는 동작을 기록한 다음 vinorleague의 내용과 어울리는지 판단한다.
